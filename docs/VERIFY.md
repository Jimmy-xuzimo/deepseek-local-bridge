## 手动确认项

- 首次登录：设置页点“打开浏览器并登录” → 登录成功 → 状态“已就绪”。
- 重启恢复：重启服务后无需重新登录（浏览器配置持久化）。
- 登录过期：清除登录数据后，请求返回 503 且提示“未登录”，重新登录后恢复。
- 队列：连续发两条消息时，第二条在第一条之后开始（设置页显示排队数）。
- 取消：在 Chatbox 里停止生成，网页端也随之停止。
- 便携包：在没有 Python 环境的机器上解压运行 `DeepSeekBridge.exe`，能打开设置页并完成登录。
- Codex CLI：通过 CC Switch 路由后，在测试项目里完成“读取文件 → 修改代码 → 运行测试 → 根据结果继续处理”。
- 手机/其它电脑：用局域网地址 + API Key 成功发起一次对话。

本轮复审同时修复的问题：

1. 附件上传判定：网页芯片显示的是上传文件的真实文件名（原先传的是内部 `file-<id>.txt`），导致附件检查误报失败；现在上传前复制成原始文件名，并兼容图片缩略图与文档解析等待。
2. 发送重试：图片/文档仍在处理时按 Enter 可能无效，现在按 `Enter → 发送按钮 → 等待 2 秒重试` 的顺序发送，并能区分网页限流与结构变化。
3. 思考与回答分离：思考块内部节点曾被当成回答正文，现在按 DOM 精确区分，`reasoning_content` 与 `content` 互不污染。
4. 会话连续性：修复“每条消息都新建网页对话”（客户端注入时间戳 system-reminder 导致）；新增多会话映射，切换会话可切回原网页对话。
5. 限流：识别“消息发送过于频繁”，返回 429 与可操作提示；新增请求最小间隔（默认 2 秒）。

## 已知限制

- 网页版改版会导致选择器失效，需要更新 `selectors.json`（诊断文件可加速定位）。
- 带工具定义的请求会缓冲完整回答后再返回，首字延迟更高。
- 网页版单会话串行，多步编程任务整体速度受网页端限制。
- 网页端不提供温度、采样等参数，相关字段会被忽略；`n>1` 直接拒绝。
