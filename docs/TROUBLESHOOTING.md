# 常见问题与排查

## 显示“未登录 / 登录已失效”

1. 打开设置页，点“显示浏览器窗口”，在窗口里重新登录 DeepSeek。
2. 点“重新检测登录”，状态变为“已就绪”即可。
3. 如果登录窗口已被关闭：点“打开浏览器并登录”重新拉起（浏览器窗口需要保持运行，最小化不影响）。

## 浏览器没有弹出 / 启动失败

- 确认已安装 Edge 或 Chrome；设置页“浏览器”可选择指定通道。
- 查看日志（设置页“最近日志”），常见错误：`browser_start_failed`（杀毒软件拦截、配置文件被占用）。
- 如果浏览器配置损坏，点“清除登录数据”后重新登录。

## 提问后一直卡住 / 返回超时

- 网页版偶尔排队较慢，先看浏览器窗口里是否正在生成。
- 增大设置页里的“单次请求超时”和“回答判定静默秒数”。
- 若网页出现“服务器繁忙”“今日次数已达上限”等提示，本服务会返回 429/502，稍后再试。

## 提示“消息发送过于频繁”（429 rate_limited）

这是 DeepSeek 网页版对单个账号的频率限制，短时间连续发送（例如一次性跑验收脚本）容易触发：

- 等待几分钟后重试即可，Web 端限制通常是临时的。
- 设置页可调大「请求最小间隔（秒）」，默认 2 秒，能明显降低触发概率。
- 编程类客户端（Codex 多轮工具调用）消息密集，建议把间隔调到 3-5 秒。

## 每发一条消息就新建一个 DeepSeek 对话

历史问题，已在 0.1.0 修复，原因与规则如下：

- 原因：Chatbox 等客户端每次请求都会注入带时间戳的 `system-reminder`。旧逻辑把这段实时变化的内容也算进“会话指纹”，于是每条消息都被判定为新对话。
- 现在的规则：判断能否续聊时**忽略 system/developer 消息**，只比较 用户/助手/工具 消息；并且要求最后一条是用户消息、倒数第二条是助手消息。
- 满足条件时只把最后一条消息发进当前网页对话（日志会打印“复用当前网页对话”）；不满足（新对话、改了历史、工具调用轮次）才会新建网页对话并发送完整上下文。
- 如果某个客户端每次都改写历史内容（例如每次插入不同的工具结果），仍会新建对话——此时上下文依旧完整，只是网页侧会多出对话记录。

## 多会话：新建 / 切回旧对话

- 在 Chatbox 里新建一个对话 → 服务会在网页侧新建一个 DeepSeek 对话（历史前缀不同，不会与旧对话混淆）。
- 切回之前的对话继续提问 → 服务会切回对应的 DeepSeek 网页对话（日志显示“已切回网页对话 xxx”，随后“复用网页对话”），上下文就是那个对话自己的历史。
- 映射保存在数据目录的 `conversations.json`（只有 URL 和指纹，没有消息内容），默认最多记录 50 个最近使用的对话，服务重启后依然有效。
- 如果在网页里手动删除了某个对话，再次切回该会话时会自动退回“新建对话 + 发送完整历史”，上下文不会丢。
- 极少数情况下（两个不同的客户端对话历史完全相同，例如都只有一句一模一样的开头且都还没回答完），可能被识别成同一个对话；一旦各自产生回答就会区分开。

## 登录后仍提示找不到输入框 / 发送失败

多半是网页改版导致选择器失效：

1. 设置页点“保存诊断信息”，会生成 `diagnostics\diagnose-*.json` 和截图。
2. 打开 json，查看 `selectors` 里哪个分组的 `count` 都是 0，以及 `elements.buttons` 里的按钮文字与 class。
3. 在数据目录（默认 `%LOCALAPPDATA%\DeepSeekBridge`）新建 `selectors.json`，例如：

```json
{
  "chat_input": ["textarea#new-input-id"],
  "send_button": ["button.my-send-class"],
  "markdown": ["div.new-markdown-class"]
}
```

4. 重启服务后生效（只需覆盖失效的键，其他键保持默认）。

## Chatbox 连接失败

- 先确认服务在运行（设置页能打开）。
- API 域名先试 `http://127.0.0.1:8317`，失败再试 `http://127.0.0.1:8317/v1`（Chatbox 可能自动追加 `/v1`，两种都试一次即可定位）。
- Key 必须与设置页一致；重新生成 Key 后需要更新客户端。

## 手机 / 其它电脑连不上

1. 确认设置页「在网络中提供服务」已开启，并且**重启过服务**（`scripts\restart.ps1`）——端口与局域网开关不重启不生效。
2. 确认两台设备在同一个 Wi-Fi/局域网，且地址用的是设置页里列出的 192.168.x.x。
3. Windows 防火墙：第一次会弹窗询问，选择“允许访问”；若当时点了取消，可在“Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙”里为 Python 或 DeepSeekBridge 放行，或手动放行 TCP 8317。
4. 如果路由器开启了“AP 隔离”，同一 Wi-Fi 的设备之间也无法互访。
5. 电脑 IP 变了（例如重启路由器）时，以设置页显示的局域网地址为准。

## CORS

- 浏览器里运行的网页类客户端（例如某些本地 Web UI）需要「启用 CORS」为开启状态；桌面客户端（Chatbox、CC Switch）不受影响。
- CORS 开关保存后即时生效，不需要重启服务。
- 如果某网页客户端仍报跨域错误，检查它的地址是否使用了局域网 IP（如果网页是 `http://192.168.x.x` 打开的，API 也应填同一网段的地址，避免 http/https 混用）。

## Codex CLI（CC Switch）相关

- 404：CC Switch 里 Upstream Format 必须是 `OpenAI Chat Completions`，且 Routing 总开关与 Codex 开关都已打开。
- 切换后要重启 Codex 终端，让它重新读取 `config.toml`。
- Codex 需要多轮工具调用时，每轮都会排队，请耐心等待；如果模型偶尔不按协议输出，客户端会看到普通文本回复而不是工具调用，可以让它“按工具协议重试”。

## 数据与重置

- 数据目录：`%LOCALAPPDATA%\DeepSeekBridge`
  - `config.json`：端口、API Key、管理员令牌、开关
  - `browser-profile\`：登录状态（删除即退出登录）
  - `uploads\`：附件；`logs\`：日志；`diagnostics\`：诊断文件
- 完全重置：停止服务后删除整个数据目录。
